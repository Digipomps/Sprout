# RELEASE

## Artifact trust policy
- Trust only release artifacts that match the published `SHA256SUMS*.b64url` file for the target platform.
- Trust only artifacts covered by the published release manifest and matching the expected runtime/version/channel.
- Update/install authority is separate from bootstrap. `sprout` does not self-update.
- CLI install/update is allowed only when `UpdateGrantPolicy` grants artifact name + hash + semver + channel + trigger identity/contract.

## Build the release bundle
Default local bundle:
```bash
swift test
bash Scripts/build_release_bundle.sh dist
```

Platform-suffixed bundle:
```bash
swift test
bash Scripts/build_release_bundle.sh dist linux-x86_64
```

Artifacts produced:
- default local bundle:
  - `dist/sprout`
  - `dist/sprout-updater`
  - `dist/release-manifest.json`
  - `dist/SHA256SUMS.b64url`
  - `dist/sprout.spdx.json`
- platform-suffixed bundle example:
  - `dist/sprout-linux-x86_64`
  - `dist/sprout-updater-linux-x86_64`
  - `dist/release-manifest-linux-x86_64.json`
  - `dist/SHA256SUMS-linux-x86_64.b64url`
  - `dist/sprout-linux-x86_64.spdx.json`
- optional keyless cosign signatures/certificates for every listed artifact and checksum file

Note:
- `sprout-macos` is built in CI on macOS, but it is not currently part of the release bundle generated by `Scripts/build_release_bundle.sh`.

## Verify the release bundle locally
Default bundle:
```bash
bash Scripts/verify_release_bundle.sh dist
```

Platform-suffixed bundle:
```bash
bash Scripts/verify_release_bundle.sh dist "" dist/SHA256SUMS-linux-x86_64.b64url
```

This verifies:
- artifact hashes against the selected `SHA256SUMS*.b64url`
- optional detached GPG signature on the checksum file when `*.asc` is present
- optional cosign signatures when matching `.sig` and `.pem` files are present

## CI release evidence
GitHub Actions is configured to produce:
- macOS CLI bundle artifacts for `sprout` and `sprout-updater`
- Linux CLI bundle artifacts for `sprout` and `sprout-updater`
- platform-suffixed release manifest, checksum file and SPDX SBOM
- cosign keyless signatures for listed artifacts and checksum file
- optional detached GPG signature for the checksum file when release secrets are configured
- optional GitHub build provenance / SBOM attestations when repo variable `SPROUT_ENABLE_GITHUB_ATTESTATIONS=true`

Current limitation:
- GitHub attestations are disabled by default because the private Digipomps repository plan does not currently support the attestation API
- Linux WSS transport parity is not part of the release baseline yet; Linux support is CLI/bootstrap/update/verification first
- `sprout-macos` is built in CI, but its separate release packaging/notarization path remains a later step

## Reproducible build target
Target:
1. Build from immutable git tag in a clean environment.
2. Run `bash Scripts/build_release_bundle.sh dist <platform-suffix>`.
3. Compare `dist/SHA256SUMS-<platform-suffix>.b64url` against the published checksum file.
4. Verify checksum signature and provenance attestations.

Current status:
- local bundle generation and checksum verification are implemented for default and platform-suffixed bundles
- CI keyless signing is wired for non-PR runs on macOS and Linux
- GitHub attestations are opt-in and require repository support before they can be treated as release baseline
- bit-for-bit reproducibility across independent environments remains an explicit release goal, not yet proven in CI

## Runtime-specific release policy
### CLI / server
- Preferred: operator-managed replacement of immutable signed artifacts.
- `sprout-updater` may plan or verify installs, but install mutation remains outside `sprout`.
- Supported native Linux baseline: Ubuntu 22.04 `x86_64` without Docker.

### macOS
- Outside App Store, code signing and notarization are required before distribution.
- `sprout-macos` packaging is not part of the current release bundle script.
- Sparkle or any auto-update path is deferred until explicit grants + stronger metadata controls exist.

### iOS
- App Store only.
- No custom updater.
